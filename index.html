Three-Tier Web Application on AWS with Terraform

A multi-tier deployment in AWS Mumbai (ap-south-1), using Terraform to define the infrastructure and separate the web, application, and database responsibilities.

  • Terraform modules for networking, load balancing, Auto Scaling, RDS, IAM, and monitoring.
  • Nginx web tier forwards requests to a Node.js / Express application on port 4000.
  • Amazon RDS for MySQL provides the application database.
  • Systems Manager Session Manager and VPC endpoints support instance management without exposing SSH to the public internet.
  • Startup scripts and an S3 bucket support deployment automation and project file storage.

03 / Engineering approach

How I approach a build

A repeatable process helps make infrastructure changes easier to review, diagnose, and explain in an interview.

STEP 01

Plan the architecture

Identify requirements, traffic flow, network boundaries, access, and failure points before deploying.

STEP 02

Define as code

Organize Terraform configuration, inputs, outputs, and modules; review the proposed plan.

STEP 03

Deploy and verify

Check resource state, application health, connectivity, logs, and expected behavior after deployment.

STEP 04

Document and improve

Record what worked, investigate failures methodically, and make the next deployment more repeatable.

04 / Troubleshooting lab

Problems are part of the build.

Short case notes show the investigation path. Expand each note to see the checks I use; exact root causes should be recorded only after verification.

AWS · Access

Systems Manager session fails

A private instance may be running but still fail to establish a Session Manager connection.

Investigation checklist

Check the attached instance role and required permissions, SSM Agent status, instance DNS and network access, interface endpoint availability, endpoint security-group rules for HTTPS, and relevant agent logs. Verify the fix with a new session.

Web · Application

Nginx returns an upstream error

The web server can be running while the application behind it is unavailable.

Investigation checklist

Check whether the Node.js process is running and listening on the expected port; test the local health endpoint; inspect application and Nginx logs; verify the upstream address and security-group path between tiers.

AWS · Load balancing

Target group reports unhealthy targets

Instances can be online without passing the load balancer health check.

Investigation checklist

Review the configured health-check path and port, target registration, application response, listener and target-group settings, and inbound rules. Test the health endpoint directly from an allowed network path before changing settings.
